# GF(4) Nonbinary SC-LDPC for DNA Data Storage

This repo implements nonbinary, terminated, spatially coupled LDPC codes over GF(2^m), with a DNA substitution channel model for GF(4).

## 1. Build
Compile the code. Re-run this command any time the source code changes.
```
clang++ -std=c++14 -O2 -IInclude LDPC/*.cpp -o build/ldpc
```


## 2. Concepts

- **Spec file (`.ldspec`)**: the serialized parity-check matrix H, plus code
  parameters (length, redundancy, GF extension). Produced by mode `B`,
  used by every other mode.
- **Nucleotide mapping**: `0,1,2,3` ↔ `A,C,G,T`. As written in the `testbed.cpp`.
- **Channel matrix file**: text file with convention,

https://latex.codecogs.com/png.image?\dpi{200} \scriptsize Q = \begin{bmatrix} P(y=A\mid x=A) & P(y=A\mid x=C) & P(y=A\mid x=G) & P(y=A\mid x=T)\\ P(y=C\mid x=A) & P(y=C\mid x=C) & P(y=C\mid x=G) & P(y=C\mid x=T)\\ P(y=G\mid x=A) & P(y=G\mid x=C) & P(y=G\mid x=G) & P(y=G\mid x=T)\\ P(y=T\mid x=A) & P(y=T\mid x=C) & P(y=T\mid x=G) & P(y=T\mid x=T)\\ \end{bmatrix}^T

- `Dimension` = number of message symbols as input; `Length` = codeword length after encoding.
- Substitution errors only, no insertions/deletions.

## 3. Step-by-step commands

### Mode B: build the H matrix
Builds a terminated, spatially-coupled regular GF(2^Extension) parity-check
matrix with random generation within each coupling layer.
```
./build/ldpc B <VNsPerPos> <CNsPerPos> <CouplingWidth> <CheckDegreePerOffset> <ChainLength> <Extension> <specFile>
```
- `VNsPerPos`, `CNsPerPos`: number of variable/check nodes at each position along the chain
- `CouplingWidth` (`w`): each VN connects to `w` consecutive check-node positions
- `CheckDegreePerOffset`: edges each check node gets from each contributing position
- `ChainLength` (`L`): number of VN positions (number of CN positions `L+w-1`)
- `Extension` = 2 for GF(4)
- `specFile`: location in the repo where H matrix is saved

Constraints on the parameters (IMPORTANT):
- `Length = VNsPerPos * ChainLength`, `Redundancy = CNsPerPos * (ChainLength + CouplingWidth - 1)`.
- `VNsPerPos` must equal `CNsPerPos * CheckDegreePerOffset` Otherwise, error.
- `CheckDegreePerOffset` should be ≥ 2. The decoder program assumes every check has degree ≥ 2. Otherwise, error.

Properties:
- VN degrees: constantly equals to `CouplingWidth`
- CN degrees: degree profile is a trapezoid, it ramps linearly from `CheckDegreePerOffset` up to the max `CheckDegreePerOffset * CouplingWidth` over the first `w-1` positions, stays flat at the full value through the bulk of the chain, then ramps symmetrically back down to `CheckDegreePerOffset` over the last `w-1` positions.

### Mode H: View the H matrix
```
./build/ldpc H <specFile>
```
Prints `Redundancy × Length` matrix of GF(4) elements (0-3)

### Mode E: encode a string
Message length must match H dimension exactly, otherwise error.
```
./build/ldpc E <specFile> <message>
```


### Mode C: full pipeline: encode → simulate DNA channel → decode → recover
```
./build/ldpc C <specFile> <confusionMatrixFile> <message> <NumOfDecoderIterations>
```
`confusionMatrixFile`: channel model file (`LDPC/acc-true_passQ-true_forward.txt`)

Python code to check the errors:
``` Python
def count_substitutions(clean, noisy):
    assert len(clean) == len(noisy)
    diffs = [(i, a, b) for i, (a, b) in enumerate(zip(clean, noisy)) if a != b]
    print(f"{len(diffs)} substitution(s) at position(s) {[i for i, _, _ in diffs]}")
    for i, a, b in diffs:
        print(f"  {i}: {a} -> {b}")
    return diffs
```

### Mode D: simulation over random trials
For measuring error rate on randomly generated messages. Thus, this can be a quick way to test the LDPC code been designed.
```
./build/ldpc D <specFile> <NumOfDecoderIterations> <NumOfRemainingVals> <confMatrixFile> <NumOfErrors> <NumOfTrials>
```
`NumOfErrors`: stop early once this number errors are seen

`NumOfTrials`: max number of random trials to run 

`NumOfDecoderIterations`: number of decoding iterations allowed at each trail

i.e. run random trials, stop if `NumOfErrors` of the trails have an error or `NumOfTrials` has been run, where each trial is an independent experiment: random message → encode → channel injects random substitution errors → decode → check errors.

`NumOfRemainingVals` must be ≥ the field size (4 for GF(4))

The final line in the output will have the format:
```
<trials run> <codeword error rate> <symbol error rate> <decode failure rate>
```

### Mode T: encoding verification
Encodes random messages and confirms every codeword satisfies all parity checks (no channel involved).
```
./build/ldpc T <specFile> <NumOfIterations>
```
